Platform Team Horizons

How a team that runs multi-tenant Kubernetes across public clouds, ArgoCD, Cloud Composer and Astronomer becomes the place the company runs AI, and the team that makes it safe for AI agents to operate infrastructure.

What AI-proofing means for this team

Three shifts, all built on what the team already owns

Tickets, onboarding checklists and routine upgrades are the work AI automates first. The team's lasting value is the control plane: identity, tenancy, policy, GitOps and cost. Those are exactly what AI workloads and AI agents need.

Run AI

Host GPUs, models, vector stores and LLM traffic with the same tenancy, quotas and GitOps that services get today. Teams stop building one-off AI stacks.

Be run by AI

Make every platform API safe for an agent to call: scoped identity, policy checks, approval gates, budgets and a full audit trail. Agents propose changes; GitOps applies them.

Move up the stack

Automate onboarding, triage and upgrades so the team's time goes to architecture, reliability and governance, the work that needs judgment and someone accountable.

Evals & tracing Every agent action is traced end to end and replayed in the eval suite.
  • Agents get identities, not shared keys.Each agent run has a short-lived identity tied to a tenant and a person who started it.
  • Write access goes through Git.Agents read live state through MCP tools but change it only through pull requests that ArgoCD applies.
  • Autonomy is a dial.Read only, then open pull requests, then auto-merge for low-risk changes, set per action and per tenant.
  • Budgets stop runaway loops.Token, CPU and wall-clock limits per run, enforced by the gateway and the sandbox.
Example

One file per tenant

The Tenant resource is the center of the roadmap. Everything the team provides, from clusters to GPUs to agent permissions, becomes a field on it. An agent or a person changes it the same way: a pull request.

When this file merges, a controller:

  1. creates the namespace, RBAC and quotas on each listed cluster
  2. creates the ArgoCD project and points it at the deploy repo
  3. creates Airflow pools and connections on Astronomer or Composer
  4. sets the tenant's monthly budget in the LLM gateway
  5. sets the team's burst capacity and time limits for ephemeral environments
  6. enables an agent sandbox limited to the listed actions
apiVersion: platform.example.com/v1alpha1
kind: Tenant
metadata:
  name: payments-risk
spec:
  owners: [team-payments-risk]
  clusters:
    - gke-prod-europe-west1
    - eks-prod-us-east-1
  quotas:
    cpu: "200"
    memory: 800Gi
    gpu: { type: nvidia-l4, max: 8 }
  gitops:
    argocdProject: payments-risk
    repo: github.com/example/payments-risk-deploy
  airflow:
    target: astronomer        # or: composer
    pools: { default: 16 }
  llmGateway:
    monthlyBudgetUSD: 2500
    models: [claude-sonnet-5-5]
  environments:
    burst: { cpu: "64", memory: 256Gi }  # borrowable on top of quotas
    maxConcurrent: 10
    defaultTTL: 8h
    maxTTL: 7d
  agents:
    sandbox: enabled
    allowedActions: [read, open-pr]  # widen after evals pass
Self-service · deep dive

Ephemeral environments on demand

Teams borrow CPU, memory and GPUs in their own namespace for as long as they need them: a dev workspace, a large test run, an experiment. When the time is up, the capacity goes back to the pool. Teams keep a smaller permanent quota instead of sizing for their busiest day.

From the terminal or portal

Run platform env up --cpu 16 --memory 64Gi --ttl 8h, or fill in a form in the portal. The request shows the estimated cost per hour before it starts.

Declared in Git

Commit an Environment file to the team's deploy repo and ArgoCD creates it. Delete the file to release the capacity. Good for setups a team repeats, like a weekly load test.

From a pipeline or agent

CI jobs and AI agents call the same API to get capacity for one run and release it at the end. Agents use it through an MCP tool, inside their sandbox limits.

  1. RequestHow much CPU, memory and GPU, and for how long.
  2. AdmitChecked against the team's quota. Borrows idle capacity if needed, or waits in a queue.
  3. StartPods start in the team's namespace from a team template. Nodes are added if the cluster is full.
  4. UseShell, notebook or internal URL. Usage is metered against the team.
  5. SleepScales to zero when idle. Storage is kept, so work resumes where it stopped.
  6. ExpireAt the time limit, pods are deleted, capacity is released, and the volume is snapshotted or removed.

Building blocks

PieceWhat it does
Team namespaceWhere every environment runs. RBAC, network policy and default limits already come from the team's Tenant file.
ResourceQuotaThe team's guaranteed base capacity, always available.
KueueQueues requests, lets a team borrow other teams' idle capacity up to a cap, and takes it back when the owner needs it.
Node autoscalingAdds nodes for a burst and removes them after release. Karpenter on EKS, node auto-provisioning on GKE, cluster autoscaler on AKS.
Environment controllerApplies time limits, sleep and cleanup, and labels everything so cost lands on the team's report.

The hard parts

  • Fair sharingBorrowing needs limits. Cap how much any team can borrow, and reclaim borrowed capacity first when its owner asks for it.
  • Protecting productionEnvironments run at a lower priority class, ideally on separate node pools, so a burst never evicts production pods.
  • Idle wasteDefault time limits, sleep when CPU stays idle, and a cost estimate on every request keep forgotten environments rare.
  • CleanupThe controller deletes anything past its time limit and anything without an owner label, inside each team's namespace.
apiVersion: platform.example.com/v1alpha1
kind: Environment
metadata:
  name: risk-model-backtest
  namespace: payments-risk     # the team's own namespace
spec:
  owner: team-payments-risk
  template: python-workspace   # team-approved image and tools
  resources:
    cpu: "16"
    memory: 64Gi
    gpu: { type: nvidia-l4, count: 1 }  # optional
  storage:
    size: 100Gi
    keepWhileAsleep: true
  ttl: 8h                      # capped by the tenant's maxTTL
  sleep:
    afterIdle: 1h
  priority: ephemeral          # never evicts production
  queue: payments-risk         # Kueue LocalQueue
status:
  phase: Ready
  admittedFrom: borrowed       # base | borrowed
  expiresAt: "2026-11-01T23:00:00Z"

Starting point

The first 90 days

  1. Take inventoryEvery tenant, cluster, ArgoCD instance and Airflow environment, with an owner for each.
  2. Stand up the LLM gatewayMove existing provider keys behind it and turn on per-team spend reporting.
  3. Draft the Tenant specPilot it with two friendly teams on one cluster per cloud.
  4. Pilot ephemeral environmentsOne team on one cluster: base quota plus a burst pool through Kueue, an 8-hour default limit, and automatic release.
  5. Ship the read-only MCP serverStart with ArgoCD sync status and Airflow DAG run history.
  6. Convert the top ten runbooksPick the ones behind the most pages and tickets.
  7. Publish the first cost reportEven rough attribution starts the right conversations.
